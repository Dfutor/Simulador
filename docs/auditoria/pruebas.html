    C.1. Entorno y procedimiento

    21 de noviembre de 2026, árbol de trabajo sobre ce23bf2, versión declarada del motor 2.1. Python 3.12.3, SciPy 1.18.1, NumPy 2.5.4, Ciw 3.2.7, FastAPI 0.162.4, Pydantic 2.14.3. Node 22.22.0, Vite 8.3.7 y Chrome local en modo sin interfaz. Los comandos se lanzaron con las dependencias ya instaladas. El navegador usó servidor local aislado 127.0.0.1:8768 y un directorio de datos temporal. El despliegue Docker está documentado a partir de sus manifiestos y no fue necesario para las pruebas del entorno auditado.

    # Desde la raíz del repositorio
(cd simulador2 && ../.venv/bin/python -m unittest -v)
(cd front && npm run build)
.venv/bin/python docs/auditoria/evidencia/reproducir.py --salida /tmp/evidencia-banco
sha256sum -c docs/auditoria/evidencia/fuentes.sha256

    Artefactos. Registro de unittest · Guion de evidencia · Resultados en JSON · Traza CSV de la primera réplica base · Registro de intentos KS · Huellas del árbol y fuentes. La huella se verifica desde la raíz. El guion exporta solo evidencia de investigación y llama a las funciones existentes. Las pruebas de API de la suite aíslan sus archivos mediante directorios temporales. Una segunda ejecución en un directorio nuevo produjo el mismo CSV, las mismas huellas, el mismo registro de rechazos y el mismo contenido numérico del JSON. Las únicas diferencias del JSON fueron las tres marcas de publicación en las respuestas de visita.

    Las comparaciones aritméticas de trayectorias usan igualdad exacta para enteros y tolerancia absoluta 10⁻¹⁰ en cálculos ejemplares de coma flotante. Las cifras impresas se redondean para lectura. Un resultado «reproducido» puede ser un fallo verificado. La clasificación general de estados se define en el criterio de la matriz.

    C.4. Trazas y tolerancias

    T02a. El JSON conserva la configuración, semilla 1, uniformes de cada cliente, tiempos absolutos en min desde las 08:00 y serie de eventos. Las dos tablas del capítulo 13 permiten reproducir cada fila. Invariantes: A≤B≤D, esperas no negativas, ninguna caja atiende a dos clientes simultáneamente, prioridad se decide entre pendientes elegibles, se observan cinco salidas y se termina vacío. El cierre 8 min no es el final del horizonte, que vale 13,1058333411. Tablas 6–7 y línea de tiempo.

    T02b. En el caso manual con cuatro clientes y C=5, salen así: cliente 1 a t=4, prioritario 3 a t=6, cliente 2 a t=9 y cliente 4 a t=10. Wq=(0+5+2+6)/4=3,25; T=10; Lq=1,30. Se comprobaron ambos estimandos y conservación de todo el sistema, sin aleatoriedad de entrada. A.6.

    T07. El CSV muestra 404 clientes en dos jornadas en la primera réplica aceptada. La primera fila de mañana usa U=0,4166198725 para la llegada a t=0,497461 y U=0,1441498655 para servicio de 4,459597 min; sale t=4,957058. Al sumar tiempos dentro del CSV y dividir por N o T según corresponda se reproduce la primera réplica, no la media de 30. El JSON incluye el parámetro completo y el resumen para repetir las 30.

    C.6. Recorrido de integración y capturas

    1. Abrir el frente compilado servido por FastAPI. Confirmar conteos y análisis de tendencias. Abrir y cerrar Ajustes.
    2. Avanzar a Servicio, dejar cinco cajas y U(1,25). En Prueba KS escribir 12345 y activar Ciw. Simular y confirmar semilla y veredicto. Inspeccionar gráficas por jornada y KS.
    3. Entrar a Establecimiento, pulsar Guardar y publicar y comprobar que la API devuelve la semilla 12345 y el estado vigente. Conservar franjas de 60 min y horario de fábrica.
    4. Comparar 7 y 15 de diciembre de 2026 con categoría Todas. Confirmar la presencia de las dos barras simuladas y la serie observada en el navegador. Consultar enlaces directos del 5 y del 15.
    5. Comprobar el esquema en /openapi.json. Archivar capturas numeradas 01–14: ocho del asistente/ajustes, cinco de establecimiento y cliente, una de contrato API.

    La revisión visual posterior confirmó que la tabla de llegadas, el veredicto, las cuatro gráficas de jornada, el doble panel KS, la comparación y el calendario abierto/cerrado tienen el contenido esperado. La verificación de controles menos frecuentes se hizo también por inspección de Vue y pruebas del backend. No se ensayó aquí rendimiento de equipos remotos, rendimiento del motor gráfico en otros equipos, resolución móvil de cada pantalla ni accesibilidad con lector de pantalla.
